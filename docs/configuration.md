`capture.folder` empty means the folder of macOS's own screenshots, else the Desktop; it may start with `~/`. `capture.shortcuts` holds only the changed ones (`area window screen timer text scroll record gif`; an empty string removes one, a built-in one too); `capture.quick_seconds` 0 keeps the quick panel until it is closed. In `audio`, a volume is 0 to 4 (1 is unchanged), `output` is a device UID (empty follows the system's output), `eq` is a preset (`flat bass_boost bass_reducer treble_boost treble_reducer vocal loudness rock pop electronic hip_hop jazz classical acoustic spoken movie gaming`, or `custom` for `custom_eq`, 10 bands in dB within 12 either way), `boost` is 0 to 1 and `width` 0 (mono) to 2. Each entry of `devices` (by device UID, followed automatically as the default output changes) may also carry `bass` and `treble`, in dB within 12 either way, which apply to that output alone. `stack.modifier` is `option`, `command`, `control` or `shift`; `stack.sensitive` is `off`, `mask` or `never`; `stack.expire_minutes` is 1 to 1440. `snap.templates` lists by id the layouts every screen offers when a window is dragged to the notch (`full halves rows thirds quarters main_left main_right left_stack right_stack grid_six`, or the id of one in `snap.custom`), and `snap.screens` gives a screen a list of its own by the name of the screen; unknown and repeated ids are ignored and a list with none left is the default one. `snap.custom` holds the layouts made from a grid: `id` is a `c` and up to four digits, `name` is up to 24 characters, `cols` and `rows` are 1 to 6, and `cells` are `[column, row, column, row]` (the first part and the one after the last) that together cover every part of the grid once; one that does not is ignored; `pin.shortcut` pins the window in front, or lets go of the pinned one (empty for none, which leaves the switch in the menu bar panel); which window is pinned is not saved; `cursor.theme` is `neon`, `custom` or a character of the mascot (`spider frog ufo ghost wizard mario`), `cursor.size` is 16 to 96 points, `cursor.speed` is 0.25 to 3, `cursor.tip` is `top` or `centre` (where a picture of your own clicks) and `cursor.custom_path` is the file of the `custom` theme, which only the page's button writes; `menubar.auto_seconds` is 0 (never) to 3600. In `notch`, `material` is `glass`, `clear` or `black`; `motion` is `spring`, `smooth` or `none`; `hover_delay_ms` is 0 to 1000; `open_page` is `activity`, `last` or a tab id; `display` is `auto` (the built-in screen with a notch, else the main one), `main` or `pointer` (the screen whose top edge the pointer reaches); `rest` is what a screen without a notch shows, `notch` or `hidden`; `pages` lists the tabs to show in order (empty shows all; ids `clipboard shelf media agents calendar sound`, and `notes launcher weather prs updates pomodoro screentime dayprogress system devices displays`, which are in the strip only while the `enabled` of the feature of that name is on, whatever `pages` says, and come back to the place `pages` gives them when it is turned on again); `waveform` is `live` or `animated`; `shortcut` opens and closes the notch (empty for none); `show_in_fullscreen` (on by default) set to false takes the notch off the screen, with its trigger at the top edge and its live activities, while the app in front is full screen on the notch's screen, and puts it back when that app leaves full screen, the space changes or another app comes to the front; this app's own settings window in front never hides it. It is looked at again only when the space changes or another app comes to the front, from the list of windows: a full-screen app has a window exactly as large as the screen, or a window as wide as the screen that reaches its bottom edge together with the title bar macOS parks just above the top edge of a full-screen window. `theme` is `auto`, `light` or `dark`. `launch_effect` lets the ghost come out of the notch and blink each time the app is opened by hand (never at login, never with `--background`, and only while `notch.enabled` is on). `panel_keys` are the keys of the actions inside the notch and the clipboard popup, written like the other shortcuts (`delete` is the Delete key): `pin` pins or unpins, `board` files the selected item in the next board, `paste_other` pastes the other way and `delete` deletes, denies an agent or dismisses an alert. Each needs a modifier, Command alone is refused (it already means a tab, a pinned item or Delete there), and arrows, Return, Escape, Page Up and Down keep their meaning. A value of the wrong type or an unknown word in any of these falls back to the default instead of making the file unreadable.

`islands.full_at` is the charge from 80 to 100 that is announced as full while plugged in, `islands.low_at` the charge from 5 to 30 at and under which a Mac on battery is announced as low, and `islands.seconds` how long a notice stays (2 to 10; the camera and microphone notices stay as long as they are in use). Each notice has its own switch and does nothing while `islands.enabled` is off. `islands.camera` and `islands.microphone` say whether an app using the camera, or the microphone, shows on the notch; a device whose notice is off is not looked at. A file written before they had a switch each has one `islands.privacy` for both: when it is `false` both are read as off, and the file is written back with the two keys only. A Mac without a battery never shows the battery notices. `utilities.awake_minutes` is one of 15, 30, 60, 120, 240, or 0 for until it is stopped (any other number is read as 60, so that a mistake never keeps the Mac awake for ever), `utilities.awake_display` keeps the screen lit as well as the Mac awake, and `utilities.lock_seconds` (15 to 300) is the longest the keyboard stays locked. `utilities.snooze_minutes` is how long a snooze of the notch lasts, one of 5, 15, 30, 60, 120, or 0 for until it is woken (any other number is read as 30); while snoozed the pointer reaching the top of the screen does not open the notch, and a click on it and anything that opens it by itself still do. The four shortcuts follow the rule below; an empty one has no shortcut, and the keep-awake and snooze ones are empty by default. `system.seconds` is how often the System tab of the notch reads the Mac while it is open, one of 1, 2 or 5 (any other number is read as 1); `system.processor`, `system.memory`, `system.network` and `system.details` (graphics, startup disk, heat, fans and battery) choose its cards, and with all four off the tab says so. The tab does nothing while `system.enabled` is off, and nothing while it is closed. `notes.text_size` is the size of the text in the Notes tab, 12, 14 or 16 points (any other number is read as 14), and `notes.new_on_open` starts a blank note each time the tab opens. The notes themselves are the files `note-<number>.md` in the folder `notes` of the data directory, plain text, one for each note; the file's modification time is when it was last written, a file with any other name is left alone, a file longer than 50,000 characters (or over 200 kilobytes) is left alone too and not listed, so that it can never be cut by an edit, and at most 200 notes are listed (the newest, chosen from the folder's own information so that a folder with thousands is not read whole). Delete or edit them from any app; the tab reads the folder again each time it opens. `weather.units` is `metric` (degrees Celsius, kilometres an hour) or `imperial` (degrees Fahrenheit, miles an hour); anything else is read as `metric`. `weather.places` are the cities, added from a search on the settings page and not meant to be typed by hand, in the order the tab flips through them (it opens on the first): each a name, an optional region and country, and a latitude from -90 to 90 and a longitude from -180 to 180. At most eight are kept, and two at the same coordinates (to four decimals) are one city; a city that is not of that shape, a repeated one and any beyond eight are dropped when the file is read and the file stays readable. A file written before there could be several cities has one `weather.place` of the same shape; it is read as the first of `weather.places`, and the file is written back with `places` only. `launcher.items` is what the Launcher tab pins, in the order of its tiles, at most twelve: `kind` is `app` (`target` is the bundle identifier, such as `com.apple.Notes`), `folder` (`target` is a full path) or `shortcut` (`target` is the name of a Shortcut, which may not begin with a hyphen); `name` is what the tile says and may be left out. A pin of any other shape, a repeated one and any beyond twelve are dropped when the file is read and the file stays readable. Nothing is launched until a tile is pressed. `screentime.idle_minutes` is how long the keyboard and pointer may be still before time stops counting, one of 1, 2 or 5 (any other number is read as 2). What is counted is in the file `screentime.json` of the data directory: for each of the last thirty days, the seconds of each app by bundle identifier, and the names the apps had; it is written about once a minute and when the tab closes, whole or not at all, and a file that is wrong in places keeps what is right. Deleting the file, or Clear it all on the settings page, forgets everything. `pomodoro.work` is one of 15, 20, 25, 30, 45, 50 or 60 minutes, `pomodoro.short_break` one of 3, 5, 10 or 15, `pomodoro.long_break` one of 10, 15, 20 or 30, and `pomodoro.rounds` (the work sessions before a long break) one of 2 to 6; a number that is not one of these is read as the usual one (25, 5, 15 and 4). `pomodoro.auto_start` starts the next stage by itself, `pomodoro.sound` plays a sound when a stage ends, `pomodoro.open_on_end` opens the notch on the tab for a few seconds, `pomodoro.closed_notch` shows the countdown in the closed notch, and `pomodoro.shortcut` (none by default, otherwise as the shortcuts below) starts, pauses and resumes. The sessions and minutes of each of the last thirty days are in the file `pomodoro.json` of the data directory, written whole when a work session ends; the Focus tab keeps no settings and no history. `prs.github` and `prs.gitlab` choose where the Pull requests tab looks, through the `gh` and `glab` tools, which are looked for in `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` and `~/.local/bin` and run with fixed arguments and no shell: `gh search prs --review-requested=@me --state=open` and, for GitLab, the user and the open merge requests that ask for that user's review through `glab api`. `prs.drafts` lists drafts too, and `prs.minutes` (one of 5, 10, 30 or 60; any other number is read as 10) is how often the tools are asked while `prs.enabled` is on. Nothing the tools print is stored; a tool that is not installed or not signed in is simply left alone and the tab says so. The Weather tab goes online only when `weather.enabled` is on and a city is set, only while the tab is open, only for the city it shows, and asks again for a city no sooner than ten minutes after that city's last answer. A search for a name with letters only Vietnamese writes (such as `Hải Phòng`) is asked in Vietnamese whatever the language of the app, because the service finds such a name only among the Vietnamese names of places. `dayprogress.wake` is the hour the line of the day begins at, one of 5 to 10, and `dayprogress.bed` the hour it ends at, one of 21 to 24 (24 is midnight); a pair that is not offered is read as 7 and 23. `dayprogress.reminders` marks on the line the reminders that are due today at a time, and counts every reminder that is not done and due before tomorrow, overdue ones included. The Day progress tab reads the calendars of the Calendar tab, leaving out those `calendar.excluded` names, only while it shows (when it opens and then every half minute), needs the access that the Calendar page asks for, and keeps nothing on disk. `devices.low_at` is the charge at and under which a connected Bluetooth device is called low, one of 10, 15, 20 or 30 (any other number is read as 20). The Devices tab asks `system_profiler SPBluetoothDataType -json` for the devices that are connected, only while it shows (when it opens and then every half minute), with a limit of fifteen seconds, and keeps nothing on disk; a charge is shown only for a device that reports one. `displays.keys` lets the brightness keys set every external display that answers over DDC/CI while `displays.enabled` is on (it needs Accessibility; while a built-in screen is lit the keys stay with it unless Control is held). The Displays tab asks each external display for its brightness (VCP 0x10) and contrast (0x12) when it opens and sets only those two; nothing is kept on disk, and a display keeps what it was set to after the app quits, as it would after its own buttons. A charge a device has stopped reporting is kept in memory (never on disk) for two hours and shown dimmer with the time it was reported.

`agents.approval_wait_seconds` is how long a request waits on the notch before the agent asks in its own terminal; while the pointer is on the open notch with the request on its card, and after each choice, the wait starts again, up to the limit the agent gives the hook (120 seconds). A question from pi waits until pi closes it, at most an hour, because pi asks it in its terminal at the same time. `agents.peek_when_done` shows in the closed notch which agent finished or failed and in which project; `agents.sound` plays a sound for a question and for a failure, never for an agent that finished. pi has no hook file: its extension is the file `.pi/agent/extensions/figghost.ts` of the user's home, written and removed by the settings page (a file of that name without Figghost's first line is never replaced or removed) and brought up to date each time the feature starts, with the path of the app's socket written in. The hooks of a Claude Code that pi runs through the Agent SDK (`PI_CODING_AGENT=true` and a `CLAUDE_CODE_ENTRYPOINT` starting with `sdk` in its environment) report nothing.

`typing` is Vietnamese typing, off by default. `method` is `telex` or `vni` (anything else is read as `telex`); `modern_tone` puts the mark where the 1997 rules do (`hoà`, `khoẻ`), and off the older way (`hòa`, `khỏe`); `english_restore` gives back an English word that the marks spoilt when the word ends (`text`, `with`). `shortcut` switches between Vietnamese and English (empty for none, otherwise as the shortcuts below); the keyboard tap reads it before the system does, so it works where the system uses the same keys (Control+Space selects the previous input source). `apps` lists by bundle identifier, at most 100, the apps where every key is left alone; an entry that is not a bundle identifier, and a repeated one, is dropped. iPhone Mirroring and the remote desktops RustDesk, AnyDesk and TeamViewer are always left alone, since their keys go to another device. Typing starts in Vietnamese each time the app starts; the language is not saved. While another Vietnamese input method runs (Gõ Nhanh, EVKey, OpenKey, GoTiengViet or UniKey, known by name), every key is left alone. Keys are read by their place on the keyboard, as on an ANSI (US) layout, which is what the engine expects; another layout types the letters of the US one. The marks are put by the engine of Gõ Nhanh (`gonhanh-core`, BSD 3-Clause License), pinned to a commit in the workspace `Cargo.toml`.

`snippets.items` lists the abbreviations that are replaced while `snippets.enabled` (off by default) is on, at most 500; each has an `abbr` and the `text` that replaces it. An `abbr` is at most 32 characters, with no space, no line break and no other control character, and is made of characters that a US keyboard types (letters, digits and punctuation; keys are read by their place on the keyboard, as for `typing`), and the first of two with the same abbreviation stays. A `text` is 1 to 20,000 characters; `\r\n` and `\r` are read as `\n`. An item that is not of that shape or breaks one of these rules is dropped when the file is read, the rest stays, and the file is not moved aside. The abbreviation is matched against the keys pressed, in any app but iPhone Mirroring and the remote desktops, with Vietnamese typing on or off (with Telex, `;dd` shows as `;đ` and is still found); a longer abbreviation wins over a shorter one that ends it, and one that holds another before its own last key can never be finished, since the shorter is replaced first. A text of one line up to 100 characters is typed; any other is pasted with Command+V, with the clipboard saved first, the text on it for half a second marked with `org.nspasteboard.TransientType` so that the clipboard history keeps no copy, and the clipboard put back unless something else was copied meanwhile. A pasteboard that cannot be saved in full (a file promised and not delivered) leaves the abbreviation as typed. The keyboard is the one Vietnamese typing uses, so it needs Accessibility, runs while either feature is on, and is paused while another Vietnamese input method runs and while a shortcut is recorded; with `typing.enabled` off it types English and has no shortcut, badge or menu entry. The apps in `typing.apps` are left alone by Vietnamese typing only, not by snippets. The texts are stored in this file as they are, in plain text.

`download` is the video download, off by default. A link pasted on its page, or copied and chosen in the menu bar panel, is saved by `yt-dlp`, which is not part of Figghost: it is looked for in `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin` and then the search path, and so is `ffmpeg`, which is optional. `folder` is where videos go; empty means `~/Downloads`, and anything but an absolute path to a folder that exists is read as `~/Downloads` too. `quality` is `best`, `1080`, `720` or `audio` (anything else is read as `best`). Without ffmpeg the H.264 video in mp4 and the AAC audio in m4a (the two apart, as YouTube offers them) are fetched and joined by Figghost itself with AVFoundation, without encoding, into one mp4 no taller than `1080` or `720` if asked (YouTube up to 1080p), and a failed join keeps the two parts in the folder; failing those, a file that already has both is saved, an mp4 if there is one. With ffmpeg, yt-dlp joins the best video and audio, so formats above 1080p (VP9, AV1) work, and `audio` saves m4a (without ffmpeg, the best audio file the site has, an m4a if there is one). `playlist` set to true saves every video of a playlist link, otherwise only the video the link points at. Only `http` and `https` links of at most 2048 characters without spaces or control characters are accepted, and the link is the last argument of `yt-dlp`, after `--`, run with `--ignore-config` and no shell. Files are named `title [id].ext` with the title cut to 200 bytes, and what is not finished is kept in a hidden folder inside the chosen folder, removed when the download ends or is cancelled. Two downloads run at a time and the others wait; quitting the app or turning the feature off stops them, and what they started with them. The list of downloads is kept in memory only, and nothing about the links is written to the log unless `FIGGHOST_TRACE` is set.

`update.auto` installs a new version as soon as the daily check finds it, instead of asking first; either way it is used from the next launch. The check itself cannot be turned off. When it last got an answer is kept in the file `update-check` of the data folder (seconds since 1970); delete the file to have the next check come at once. A program that does not run from an app (a build folder) never checks by itself.

`version` records the layout of the file. A file without it was written before window snapping by dragging was on by default, and every such file had `"snap": {"enabled": false}` written into it whether or not the user ever chose that, so it is turned on once when such a file loads; a choice made after that stands. A file older than version 3 that has a list in `notch.pages` gets the ids of the nine tabs that join the strip when their feature is on (`notes launcher weather prs pomodoro screentime dayprogress system devices`) added at its end, once, so that the tab of a feature turned on later is not left out by a list made before it existed. The sections of the newer features (`islands utilities notes launcher weather prs pomodoro screentime dayprogress devices system download`) are read key by key: a value of the wrong type, such as `"full_at": "300"` or a section that is `null`, is read as the default of that key and the rest of the section is kept, and the file is not moved aside; a number that is out of range is brought into range.

A shortcut needs at least one modifier, except function keys (f1 to f20). An empty shortcut turns that layout off. Layout names: `left right top bottom top_left top_right bottom_left bottom_right maximize center first_third center_third last_third grid_1` through `grid_9`; the numbered grid cells map row-wise to a 3×3 screen and use Command+1 through Command+9 by default.

Environment variables: `FIGGHOST_HOME` changes the data directory, `FIGGHOST_DOWNLOADS` names the folder the live islands watch for finished downloads instead of `~/Downloads`, `FIGGHOST_PASTEBOARD` uses a named pasteboard instead of the real clipboard, `FIGGHOST_AGENTS_HOME` changes where `.claude`, `.codex` and `.pi` are looked for (with `FIGGHOST_HOME` set and no `FIGGHOST_AGENTS_HOME` they are looked for in an empty folder inside `FIGGHOST_HOME`, because the agents feature rewrites the paths of the hooks it installed each time it starts and a private instance must never reach the real files), and `FIGGHOST_NOTCH_OFFSCREEN` places the notch and the Smart Select window outside every screen, and `FIGGHOST_SMART_TEXT` with `FIGGHOST_SMART_OPEN` makes Smart Select answer for a given text as soon as the app is up (all of these are for tests), and `FIGGHOST_NOTCH_OPEN=<tab id>` opens the notch on that tab a second after the app is up and closes it six seconds later (for tests, with `FIGGHOST_TRACE=1`), and `FIGGHOST_TRACE=1` prints a timeline to stderr. Arguments: `--show-settings` always opens the window, `--background` never does, `--mcp` runs the assistant server, `--figghost-hook <claude|codex>` and `--figghost-statusline` are what the agents run (they never start the interface).
