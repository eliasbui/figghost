# Development

Layout of the repository, and the programs that check it. See [README.md](../README.md) to build and run.

- `crates/macos-sys`: all `unsafe` code and FFI: panels, event tap, event posting, Carbon hotkeys, pasteboard, app tracking, CoreAudio, the list, popup, notch and its pages, the web view host and glass window, status item, application lifecycle.
- `crates/core-mouse`: the scroll engine (source classification, decision, smoother, frame pump).
- `crates/core-clipboard`: history core (SQLite store with formatting and pin letters, search, classification, ignore policy).
- `crates/core-window`: tiling layouts as pure geometry.
- `crates/core-smart`: what a piece of text means: numbers in both styles, unit conversion, money, times and zones, the translation request and answer, and the one GET through curl.
- `crates/core-capture`: screen capture without an interface: geometry and file names, the stitcher of scrolling capture, the editor's document, and key names for the key display of a recording.
- `crates/core-audio-fx`: the sound processing of Sound as plain Rust: equalizer, compressor, limiter and smoothed gain.
- `crates/core-lyrics`: lyrics without an interface: the LRC parser and lookup, the LRCLIB client, the disk cache and the non-blocking lookup service.
- `crates/core-calendar`: calendar logic without an interface: meeting links, the alert scheduler, day grouping and the wording of dates and times in both languages.
- `crates/core-agents`: the Claude Code, Codex and pi side with no interface: hook events, the unix socket server and the wire format, the session tracker, the hook installer, the pi extension (`src/pi_extension.ts`, written into pi's folder with the socket's path), the usage readers and the hook command.
- `crates/app-ui`: composition root, configuration, language tables, the feature controllers, the settings model and bridge (`src/settings`), the updater (`src/update`: the look at GitHub every day, the download and swap of the app, the popup that says what is new), the MCP server, and the web page (`web/index.html`, `app.css`, `app.js`, `fixture.json`).
- `scripts/release.sh` lists the commit subjects since the last tag as the changes of a release, and the update popup shows that list; a file `docs/releases/<version>.md` with a list of `- ` lines, committed before the script runs, is used in their place, for changes worded for the people who use the app.
- `scripts/bundle.sh` builds `Figghost.app`; `scripts/check-agents.py` runs the agents feature through the real program and pretend agents; `scripts/check-smart.py` does the same for Smart Select; `scripts/check-capture.py`, `check-vision.py`, `check-lyrics.py` and `check-calendar.py` start the real program on private instances with their feature on and off and check that it survives a hostile config and idles; `scripts/check-focus.sh` checks that a background start (`--background`, what a login item uses) does not change the frontmost app.
## Development tools


Programs in `crates/*/examples`. Some of them post real input events, so read the warnings.

- `app-ui/settings_preview`: runs the real settings page in WebKit with no window. `selftest` runs the page's own checks; `snap <page> <out.png> [--dark] [--lang vi] [--size WxH] [--backdrop light|dark|color] [--patch json]` renders a page.
- `app-ui/update_preview`: runs the real update popup in WebKit with no window. `selftest` runs the page's own checks; `snap <available|installing|ready|blocked> <out.png> [--dark] [--lang vi] [--few]` renders one state. The installing code has its own tests with a served, signed app in a scratch folder; `cargo test -p app-ui -- --ignored --nocapture github_answers` reads the real latest release.
- `app-ui/tray_preview`: draws the panel under the menu bar item in WebKit with no window, with the entries of a machine with every feature on. `tray_preview <out.png> [--dark] [--height N] [--access] [--recording] [--hover N]` (`--access` adds the entry that asks for Accessibility, `--recording` the one that stops a recording, `--hover N` names the Nth tool as the pointer would).
- `macos-sys/web_probe`: checks the web bridge end to end in a transparent window.
- `macos-sys/window_check`: opens the real glass window without showing it, resizes it and checks that the web view follows.
- `macos-sys/web_release_check`: opens and drops the glass window four times and checks that the web view is released each time and that no WebKit helper outlives the last window (it waits for WebKit's GPU helper, so it takes about a minute).
- `macos-sys/hotkey_swap`: checks that a global shortcut can be released and registered again, which is how the settings change one.
- `macos-sys/layout_check`: opens the notch with its tabs and checks that every page lies inside the window and the tab bar is centred.
- `macos-sys/render_smart`: draws the Smart Select window in every state and checks its keys with events delivered in the process. `macos-sys/ax_dump <pid>` prints the accessibility tree of a process (the terminal needs Accessibility access and the screen has to be unlocked).
- `macos-sys/capture_check [folder]`: freezes every display, lists the windows and captures the front one alone, writing PNGs and checking their sizes. `overlay_check` drives the selection overlay with synthetic input (it posts input, so leave the machine alone), `ocr_check` reads known Vietnamese and English text back, from the picture in memory and from the same picture in a file, and prints the recognition languages this system knows, `editor_check` draws every mark of the editor at the capture's resolution, and `record_check` records three seconds with the key display, makes a GIF and checks the sound tracks of the computer's audio and the microphone. `text_window` and `scroll_target` are targets for text recognition and scrolling capture; `post_input` posts keys, moves, clicks, drags and scrolls. `scripts/check-capture.py <program>`: the start of the capture feature through the real program.
- `macos-sys/tap_check`, `tap_meter`: the process tap path with a quiet test tone, and the level one process sends to its devices. `mixer_demo` draws the Sound tab.
- `macos-sys/stack_check`: the clipboard list with boards and hidden rows, and the keyboard watchers of Copy Stack, in process on a panel outside every screen. `macos-sys/named_board <name> write <text> | read | release`: writes to a named pasteboard (never the general one) to play an app that copies. `scripts/check-stack.py <program> <named_board>`: the end to end check (about two minutes, because it waits for a one minute expiry); it posts no input events.
- `macos-sys/pin_check <window number> <seconds>`: keeps a window of another process on top the way the app does (the red border, the picture over whatever covers it, a click on the picture bringing the real window forward) and prints each state it sees; the window number is the one the window server gives, and the pictures need Screen Recording. `PIN_CHECK_TIMES=1` also prints how long each look at the list of windows takes.
- `app-ui/snap_check` (`scripts/check-snap.sh`): window snapping through the real controller, panel and notch on a pretend screen (refuses to run without `FIGGHOST_NOTCH_OFFSCREEN=1`); `macos-sys/render_snap` draws the row of layouts, the chip it shrinks to, the cells over the screen and the footprint to PNG files (the pictures of the README among them); `macos-sys/grab_check` runs the Accessibility lookup of window snapping against one point of the real screen and prints only yes or no.
- `macos-sys/cursor_check apply [neon|<file>] [seconds] [window]` replaces the system arrow and hand with a picture for that long (`SIZE` and `N` in the environment set the size and the number of frames; `window` also shows a white window with the pointer parked in it, so `screencapture -C -R` shows the cursor on a clean ground); `cursor_check window <seconds>` shows only that window, to be the other app, since the app's own windows keep the system pointer; `cursor_check restore` gives the cursors back. A registered cursor outlives the process that made it, so run `restore` after a run that left one.
- `macos-sys/picker_check <folder>`: the colour picker through synthetic events and a synthetic frozen screen on panels outside every screen, including a picture that arrives late or never; writes the loupe to PNG files. `app-ui/lyrics_preview <folder> en|vi`: the Media tab with lyrics in each state. `macos-sys/render_calendar <folder>`: the Calendar page in each state, with its buttons and keys checked. `macos-sys/eventkit_check`: prints the permission states and what an unauthorised store returns; it stops before reading if access already exists.
- `app-ui/mascot_check [folder]`: draws every character of the clipboard mascot in every scene, at the moments that tell the story, to PNG files (default `/tmp/mascot-check`). `macos-sys/mascot_stage_check`: plays a short story on the stage far outside every screen and checks that the screen's frames reach it, that the story ends, and that nothing draws after it. `scripts/check-mascot.py <program> <named_board>`: the mascot through the real program on a private instance (about 15 seconds); it posts no input events.
- `macos-sys/anim_check`: runs the notch's open and close animation outside every screen and checks the spring as the window server draws it (rest, overshoot, full size, back to rest) and that Liquid Glass has the shape's size on every sample. `ANIM_ON_SCREEN=1` runs it on the real screen, `ANIM_VERBOSE=1` prints every sample.
- `macos-sys/page_check`: opens the notch outside every screen on the clipboard strip, switches to the short Media page, gives it lyrics and takes them away, and closes it, sampling the shape as the window server draws it, and checks that the shape is the size of the page at each step and was on its way in between.
- `macos-sys/seek_check`: seeks what plays from the Media tab's bar, driven through accessibility; run it while a player that takes seeks is Now Playing.
- `macos-sys/notch_shots <folder> [glass|clear|black] [spring|smooth|none] [--video]`: shows the notch on the real screen over a colourful window of its own (so only that window is captured) at rest, with a live activity, open and closed again, and writes a screenshot of each. It takes no focus and moves no pointer. `--video` records the movement to `motion.mp4` with ScreenCaptureKit instead; with `FIGGHOST_SLOW_MOTION=25` the notch plays every movement 25 times slower and the opening is captured as a run of screenshots. Both need an unlocked screen.
- `macos-sys/nowplaying_check`: runs the Now Playing watcher with the adapter and prints what plays once a second. `macos-sys/meter_check`: plays two quiet tones and checks that the level meter's low and high bands rise for them. `macos-sys/status_icon <folder>`: draws the menu bar icon at 1x and 2x.
- `macos-sys/render_notch <folder> [--hardware]`: draws every notch page, including the agents tab with and without a pending request, to PNG files. Each page is drawn in the shape it opens to (as wide on every page, as tall as the page needs), with the fillets at the top corners. `--hardware` draws them as on a screen with a camera cutout, where the header sits beside the cutout when it fits. The key hints at the bottom of a page show only while the notch has the keyboard, so these pictures leave them out.
- `macos-sys/render_drip <png> [width height]`: draws the outline of the notch every 30 ms of its opening and every 20 ms of its closing into one film strip, so the drop it grows out of can be looked at without a screen. `macos-sys/render_closed <folder>`: draws the closed notch at rest, with ears, and with two lines of text under them, for a screen with a hardware notch and one without. The geometry of the outline is `macos-sys/src/silhouette.rs`, unit tested; `docs/research-onenotch.md` says what the design was taken from.
- `scripts/check-agents.py <program>`: the agents feature end to end (see Status). It presses buttons through accessibility, posts no input events and needs no unlocked screen, but needs Accessibility for the terminal; without it that step is reported as skipped. `scripts/check-pi.py <program>` runs the pi extension in node with a pretend pi against the real program on a private instance: a turn, a question answered on the notch (by accessibility) and one answered in the terminal, pi without the app, and the hooks of pi's claude-bridge staying quiet. `render_notch` also checks that a click on a choice that spans a redraw lands and that the row of a waiting session is a button; `render_islands` draws the finished and failed notices of the agents.
- `macos-sys/render_ui`, `render_pages`, `notch_demo`, `hud_demo`: draw the list, the focus and media pages, the notch and the volume indicator. `macos-sys/render_hud <folder>` draws every volume indicator style (notch, glass, corner, bar) at three levels to PNG files without showing anything; the glass styles are drawn with the black shape standing in for the glass, which the window server draws on screen. `notch_shots <folder> [glass|clear|ink|accent|black]` photographs the real notch in any of the materials.
- `macos-sys/render_wheel <folder>`: draws the drag wheel of each kind at 4, 6, 9 and 12 slots, at rest and with a slot lit (the wheel is always dark) to PNG files without showing anything. `macos-sys/wheel_check`: drags a file out of a second process (`drag_source`, build it first), taps Shift, Command and Control in the middle of the drag and drops on known slots and in the hub, and checks what the wheel offered and chose, that a drag without a key and a drag that starts in the app itself open nothing. It posts real input (the pointer, the left button and the three modifier keys alone) for about half a minute, so leave the machine alone; the terminal needs Accessibility access to post.
- `macos-sys/system_check [seconds]`: reads on this Mac every fact the live islands and the utilities rely on (battery, Caps Lock, camera and microphone in use, the drives that can be ejected, whether the microphone can be muted) and takes a keep-awake, holding it for that many seconds so that `pmset -g assertions` can be looked at. `macos-sys/render_islands <folder>` draws the closed notch with each live island and utility notice to PNG files without showing anything. `macos-sys/render_system <folder>` draws the System tab of the notch with sample figures in both languages, with some cards left out and in its off state (run it with `FIGGHOST_NOTCH_OFFSCREEN=1`). `macos-sys/render_prs <folder>` draws the Pull requests tab with sample requests in both languages, one request, nothing waiting and a tool that is not signed in, and presses a row and the button that looks again to check the app is told which (run it with `FIGGHOST_NOTCH_OFFSCREEN=1`). `scripts/check-prs.sh [program]` starts the real program with the tab off, with no service chosen, and with both chosen, and checks the first two run nothing and the last asks the signed-in `gh` and `glab` once after the app starts and reads their answers (it prints how many requests and services, never what they are; it is skipped when neither tool is signed in). `macos-sys/render_pomodoro <folder>` draws the Pomodoro tab ready, running, paused in Vietnamese, in a short and a long break, and off, and presses its three buttons the way an assistive tool does to check the app is told which one (run it with `FIGGHOST_NOTCH_OFFSCREEN=1`). `scripts/check-pomodoro.sh [program]` starts the real program with the tab on (with a shortcut), off, and with a shortcut that is nonsense, and checks it starts, opens - `macos-sys/make_icon`: draws the app icon at every size.
- `macos-sys/hello_check`: plays the hello on the real screen, under the notch of the screen the notch would use, and quits when it is over (2.9 seconds); it takes no focus and posts no input. ## Languages


The `language` setting accepts `auto` (default), `en` or `vi`. `auto` takes the first system language that has a translation and falls back to English. The settings window changes language at once; menus and the notch change after a restart (the page offers a button). To add one, add a variant to `Language` in `crates/app-ui/src/i18n.rs`, where every string is a method with an exhaustive `match`, and a dictionary to `web/app.js`, where a self-check lists every missing key (the update popup, `web/update.html`, keeps a small dictionary of its own, checked the same way).
